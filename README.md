# PAL by IAIRO

**Personal Adaptive Learning** — an MVP that turns open educational resources (MIT OCW, NPTEL) into a personalised, mastery-driven learning experience.

Learners pick a **learning goal** (not a course) and PAL composes a playlist across the OER library, adapting in real time based on how they answer chunk-level quizzes. The adaptation is neuro-symbolic: an LLM generates the questions and analogies, a deterministic Process Knowledge Graph decides what to do next.

---

## What's built

- **Goal-driven onboarding** — learners pick *learning tracks* (Python Programming, Linear Algebra, ML Foundations, …). PAL composes a playlist across all courses that teach the concepts inside those tracks.
- **Cross-course adaptive playlist** — lectures from MIT OCW and NPTEL are interleaved based on concept difficulty and prerequisite structure. The order re-shapes after each completed lecture.
- **Chunk-level adaptive quizzes** — every ~30s–90s of a lecture, PAL pauses the video and generates one MCQ tuned to the learner's current mastery of that chunk's concept. All questions are generated by a local LLM (Ollama) — nothing pre-written.
- **PAL-Agent decision loop** — after every attempt: observe → update beliefs → predict → assess reliability → counterfactual → select action → reflect → memory update. Each action ties to a rule in the Process KG.
- **Content-based recommendation engine** — concepts are embedded (nomic-embed-text via Ollama) as 768-dim vectors on Neo4j nodes. When the learner struggles, the recommender surfaces "bridge lectures" from other courses by cosine similarity, boosted for same-domain matches and gated by a cross-domain threshold.
- **Mastery-aware playlist re-sort** — after each lecture completes, lectures with low mastery bubble to the top (**🎯 Focus**), progressing ones show a `%` badge, mastered ones (≥85%) sink and dim with a strikethrough.
- **Sidebar workspace** — three tabs alongside the video:
  - **Notes** — timestamp-anchored notes tied to the current lecture
  - **Chat** — Q&A with PAL (Ollama) grounded in the current lecture's context, uses hobby analogies when appropriate
  - **Code** — Python playground with a 5-second subprocess sandbox
- **Post-quiz personalised summary** — after each quiz, an Ollama-generated summary framed in the learner's hobbies (Marvel, cricket, cooking, etc.) reinforces the concept just tested.
- **KG Explorer** — visualises the learner's enrolled tracks, current concept mastery (A-Box), and the deterministic Process KG rules that steer PAL.

## Explicitly deferred (out of MVP scope)

- Multi-turn *chat* onboarding (currently a 4-step form)
- Playlist "review & feedback" refinement loop
- RabbitMQ / Celery workers, per-frame OCR, video transcript ingestion
- Fine-tuning pipeline, RBAC, audit logs, admin surfaces
- Collaborative filtering (only content-based recommendation for now)

### Three-layer neuro-symbolic Knowledge Graph (Neo4j)

- **T-Box** — the static curriculum
  - `(Course)-[:CONTAINS]->(Concept)`
  - `(Concept)-[:REQUIRES]->(Concept)` — prerequisites
  - `(LectureChunk)-[:TEACHES]->(Concept)`
  - Each Concept has a `topic` tag and a 768-dim `embedding` for the recommender
- **A-Box** — dynamic learner state
  - `(Learner)-[:MASTERS {score, attempts}]->(Concept)` — updated after every quiz attempt
- **Process KG** — deterministic pedagogical rules
  - `(CognitiveState)-[:TRIGGERS]->(InterventionRule)` with `mastery_threshold`
  - Seeded rules: `Frustrated → OfferSimplerAnalogy`, `Struggling → AddRemedialContent`, `OnTrack → ContinueBaseline`, `Confident → AdvanceDifficulty`, `Mastered → SkipRedundant`
  - Every PAL adaptation is anchored here — the LLM never gets to hallucinate what to do next

### Recommendation engine

Content-based, four-stage pipeline:

1. **Item representation** — each `Concept` gets a semantic embedding from `nomic-embed-text` (via Ollama) built from name + topic + first few chunk summaries. Stored as a float array on the Neo4j node. Computed once at seed time.
2. **Candidate generation** — for each concept the learner is Struggling with (mastery < 0.55), pull all embedded concepts except the struggling one itself.
3. **Ranking** — `score = cosine_similarity × (0.7 + 0.3 × difficulty_proximity)`. Same-domain candidates get a **1.2× boost**; cross-domain candidates must clear a higher similarity floor (0.78 vs 0.55) to avoid vacuously similar matches.
4. **Filtering** — drop candidates below the threshold; drop lectures already in the composed playlist so we only surface genuinely new content.

The recommender falls back gracefully to topic-tag matching if embeddings are unavailable (Ollama down, model not pulled).

## Tech stack

| Layer | Choice | Why |
|---|---|---|
| Backend | FastAPI + Python 3.12 | Fast async, Pydantic for schema, ecosystem for LLM work |
| Frontend | React 18 + Vite | Fast HMR, react-router-dom, react-youtube for video |
| Auth | JWT (python-jose) + bcrypt | Simple, stateless, no server-side session |
| User DB | MongoDB Atlas (free) | Users, notes, chat history, quiz attempts |
| Knowledge Graph | Neo4j Aura (free) | Native graph fits the T-Box / A-Box / Process KG design |
| LLM | Ollama — `llama3.2:3b` | Local inference, JSON mode, fast enough on CPU |
| Embeddings | Ollama — `nomic-embed-text` | 768-dim, ~275MB, same infra as generation |

## Setup

### Prerequisites

- **Python 3.12** (not 3.14 — some deps don't have wheels yet)
- **Node 18+**
- **Ollama** — https://ollama.com
- A **MongoDB Atlas** account (free tier is enough)
- A **Neo4j Aura** account (free tier — 200k nodes, permanent, unlike Sandbox which expires in 3 days)

### 1. Ollama models

```bash
ollama pull llama3.2:3b         # generation
ollama pull nomic-embed-text    # recommender embeddings
ollama serve                    # runs on http://localhost:11434
```

### 2. Backend

```bash
cd backend
python3.12 -m venv .venv
source .venv/bin/activate           # Windows: .venv\Scripts\activate
pip install --upgrade pip
pip install -r requirements.txt

# Configure — copy the template and fill your credentials
cp .env.example .env
# Edit .env:
#   MONGODB_URI=mongodb+srv://user:pass@cluster.mongodb.net
#   NEO4J_URI=neo4j+s://xxxxx.databases.neo4j.io
#   NEO4J_USER=neo4j
#   NEO4J_PASSWORD=<from Aura download>

python -m uvicorn app.main:app --reload --port 8000
```

Watch for these log lines on first startup:
```

```

```bash

```

Grab the wordmark from https://www.iairo.ai/ (right-click the logo, save) and drop it into `frontend/public/iairo-logo.avif` (or `.png` / `.webp`). The BrandLogo component tries all formats and falls back to text if none are found.

## Seed content

The T-Box seed (in `backend/app/data/courses.json`) contains:

| Course | Provider | Lectures | Concepts |
|---|---|---|---|
| MIT 6.0001 — Intro to CS & Programming in Python | MIT OCW | 4 | Variables, Branching, Strings, Functions |
| MIT 18.06 — Linear Algebra | MIT OCW | 2 | Vectors, Matrices |
| NPTEL — Programming with Python (Madhavan Mukund) | NPTEL | 1 | Algorithms & GCD |
| NPTEL — Intro to ML (Balaraman Ravindran) | NPTEL | 1 | Supervised Learning Basics |

**Learning tracks** (in `backend/app/data/tracks.json`) group concepts across courses:

- **Python Programming** — Variables (MIT) + Branching (MIT) + GCD (NPTEL)
- **Linear Algebra** — Vectors + Matrices (MIT)
- **Machine Learning Foundations** — Supervised Basics (NPTEL)

The extra MIT 6.0001 concepts (`cs-strings`, `cs-functions`) are **not** in the Python Programming track — they're intentionally kept as *bridge candidates* so the recommender has non-track same-domain content to surface when a learner struggles.

Each lecture is chunked into 5 segments with quiz boundaries at **0:30, 1:30, 3:00, 5:00** — first quiz fires 30 seconds in, then 3 more within the first five minutes, so the adaptive loop is easy to demo.

## The adaptive loop, end-to-end

When a chunk boundary fires (~30s into the video), the frontend polls the YouTube player and pauses at the right timestamp. It then:

1. **Frontend** calls `POST /api/quiz/generate` with the `chunk_id`.
2. **Backend** loads the chunk (name + summary + difficulty from Neo4j) and the learner's mastery + hobbies (from Mongo).
3. **PAL-Agent** picks an initial difficulty (1–5) based on current mastery.
4. **Ollama** generates a JSON MCQ. Question and options are in direct, domain-appropriate language — hobbies are intentionally not used in the question itself (they're saved for the summary).
5. **Backend** stores the full question (with `correct_index`) in Mongo and returns everything except the correct index to the frontend.
6. **Learner** answers. `POST /api/quiz/submit` fires.
7. **Backend PAL-Agent** runs the micro-loop:
   - **Observe** the response
   - **Update beliefs** — mastery += delta (bounded to [0,1])
   - **Predict** next difficulty from mastery
   - **Assess reliability** by attempt count
   - **Counterfactual** — what if they'd got it wrong?
   - **Select action** — Cypher lookup on the Process KG picks the rule whose threshold the new mastery just crossed
   - **Reflect** — the full trace is written to `quiz_attempts` in Mongo
8. **Frontend** acts on the intervention:
   - `AddRemedialContent` → rewind to chunk start + auto-play
   - `OfferSimplerAnalogy` → rewind + show hobby analogy summary
   - `ContinueBaseline` → resume playing
   - `AdvanceDifficulty` → resume + next quiz will be harder
   - `SkipRedundant` → auto-skip past the next chunk teaching the same concept
9. **Post-quiz summary** — the hobby-analogy summary loads into the side panel.
10. **On lecture complete** — the playlist re-fetches. Struggling concepts bubble up with 🎯 Focus, mastered ones sink and dim, and the recommender may inject a **bridge lecture** from another course.

## Design decisions worth reading before extending

- **Composed playlist, not enrolled course.** A learner has `track_ids` and `target_concept_ids`, not a single `current_course_id`. The playlist is a union of lectures teaching those concepts, ordered by concept difficulty. This is what the PRD calls "custom playlist from a library of open-source courses."
- **Quiz questions never mention hobbies.** Hobbies are for the post-quiz summary and the sidebar chat only. A question phrased around Marvel or cricket dilutes what's being tested.
- **The correct answer never leaves the server on generate.** The frontend receives `{question, options, difficulty, concept}` only. On submit, the backend compares the selected index to the stored `correct_index`.
- **Bridges are same-domain by default.** Cross-domain candidates (e.g. Programming vs ML) must clear a much higher similarity bar (0.78 vs 0.55). Without this, small candidate pools cause the recommender to surface irrelevant matches.
- **The seed re-runs on every startup.** T-Box concepts and courses are MERGE-upserted (idempotent); LectureChunks are wiped and re-created (so JSON edits reflect immediately). Learner MASTERS edges live on Concepts, not LectureChunks, so wiping lectures preserves progress.
- **Onboarding uses tracks, not courses, but Course nodes still exist.** Courses are used for `source_course_title` in bridge attribution and for KG diagnostics. Users just don't pick them directly.
